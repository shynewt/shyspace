# Docs

Start here. These files describe how shyspace works and why. They must stay true: when you change the code, update the matching doc in the same commit. Only keep information worth tracking; plans and to-dos go in GitHub issues.

| File | What's in it |
|---|---|
| [guide/](guide/README.md) | The user guide: setting up and running a workspace. Its README.md lists every page, in order |
| [architecture.md](architecture.md) | How the pieces fit: core ideas, membership, sync, storage, file map |
| [security.md](security.md) | Threat model, defenses, known gaps |
| [decisions.md](decisions.md) | Choices someone might question, and why we made them |
| [development.md](development.md) | Setup, running, checks, conventions |
| [design-system.md](design-system.md) | The UI's tokens, motion and shared components |
