# Design system

The desktop UI is built from a small set of shared components in `apps/desktop/src/ui/`. Screens compose them; they don't restyle them. To see every component, run the app in development and open it with `#gallery` (`dev/Gallery.tsx`).

## Look

Calm and warm: soft neutral surfaces, one accent (violet unless you or the workspace pick another), rounded corners, gentle shadows. Light and dark follow the system setting.

- **Tokens** live in `src/styles.css` as CSS variables (`--bg`, `--surface`, `--surface-2/3`, `--border`, `--text`, `--text-muted/faint/decorative`, `--accent`, `--accent-soft/strong/text`, `--on-accent`, `--danger(-text)`, `--success(-text)`, `--warning(-text)`, `--shadow`, `--shadow-lg`, and `bg-scrim` behind modals). Tailwind exposes them as `bg-surface`, `text-muted`, `border-line`, `shadow-card`, `shadow-float` and so on. Never use raw colors in components; the logo is the one exception. Each theme's values are written once: dark ones under `@variant dark`, which matches a chosen dark theme, or the system's dark mode unless Light was chosen (`dark:` utilities follow the same rule).
- **Accent presets:** Settings › Appearance › Accent colour picks Violet (the default), Blue, Indigo, Teal, Pink or Graphite, per device (`lib/preferences.ts`, applied as `data-accent` on `<html>`, like `data-theme`). Each preset in `styles.css` sets `--accent`, `--accent-strong`, `--accent-soft`, `--accent-text` and, where white doesn't pass, `--on-accent`, for light and dark. Any element with `data-accent` shows that preset, which is how the swatches show their colour. There's no red, orange or green: those mean danger, warning and success. Text and icons on an accent fill use `text-on-accent`, never `text-white` (Graphite's dark fill is light). The focus ring and text selection follow the accent.
- **Theme pairs:** Shy (the default, in `:root`), Paper, Fjord, Moss, Dusk and Contrast, each with a light and a dark side, as `data-palette` blocks in `styles.css` that set the surface, border, text and status-text tokens (the accent stays its own choice). Settings › Appearance picks one per device; an admin sets the workspace's default theme and accent in Settings › Workspace, which everyone sees until they pick their own. Picking the theme or accent the workspace uses means following it, so a later change by the admin shows; any other pick stays. A name from the workspace the app doesn't know shows the default (`shownLook` in `lib/preferences.ts`). The theme cards (`ThemeSwatches`) draw every theme at once from `lib/palettes.ts`, which must equal the stylesheet's tokens.
- **Contrast:** text meets WCAG AA (4.5:1) on `--bg`, `--surface` and `--surface-2` in both sides of every theme with every accent, and Contrast's text meets AAA (7:1); `tests/ui/contrast.spec.ts` checks the token pairs, and that the theme cards' colours match the stylesheet, so add a pair there when you add a token.
  - `text-muted` for secondary text, `text-faint` for small informational text (timestamps, hints, section labels). Both pass on `bg` and `surface`; only `text-muted` also passes on `surface-2`, so use it for text on `surface-2` fills (like `Kbd`).
  - `text-decorative` is for decoration only: an icon beside a label, a chevron, a spinner. Never for something someone has to read.
  - Semantic colors: the plain token (`bg-danger`, a dot, an icon) is for fills and graphics, and white text passes on its fills; the `-text` token (`text-danger-text`) is for text, also on its tints like `bg-danger/15`. The same goes for `accent` and `accent-text`, except that text on an accent fill is `on-accent`.
- **Type:** the system UI font, in one scale (`@theme` in `styles.css`): `text-2xs` 11 px (badges, keys, tiny labels), `text-xs` 12 px (hints, timestamps, section labels), `text-sm` 13 px (most interface text), `text-base` 14 px (message and preview text, the body default), `text-lg` 15 px (dialog and view titles), `text-xl` 20 px (emoji in pickers and buttons), `text-2xl` 26 px and `text-3xl` 38 px (onboarding and page titles). They replace Tailwind's sizes of the same names (font size only; line height stays as set), and `tests/ui/design-rules.spec.ts` fails on a hand-picked size like `text-[13px]`.
- **Shape:** `rounded-lg` (8 px) for controls, `rounded-xl` (12 px) for cards, `rounded-2xl` (16 px) for dialogs.

The phone apps use the same colours, accents and motion: `tools/design-tokens/export.mjs` writes them from `styles.css` (`ShyTokens.kt` on Android), so edit them here only. Type sizes aren't shared; phones use their platform's text styles, so the system's text size setting works.

On Android the shared pieces are in `apps/android/app/src/main/java/dev/shynewt/shyspace/ui/`, mirroring the desktop's: `Avatar` (the same rounded square and the same colour per person, from the same hash; an agent's shows a robot), `Badge` ("Agent" beside a name), `CountBadge` (`ACCENT`, `DANGER` for mentions, `QUIET`), `DayDivider`, `SectionLabel`, `displayName` (the desktop's fallback while a profile hasn't arrived) and `rememberClock` (today and the phone's 12- or 24-hour time, made again at midnight and when the time zone or setting changes). Touch targets are at least 48 dp, and Material's `outline` (control edges) is the faint text colour, which keeps 3:1 against every surface. Screens put lists on `bg` (as the sidebar) and conversations on `surface` (as the main column). `make screens` renders every screen and a gallery of these pieces, light and dark; add a new piece to that gallery (`ScreenImages.gallery`). The launcher icon is the desktop logo as an adaptive icon: its planet and ring (`apps/android/icon/foreground.svg`, rendered to every density by `render.sh` there, with ImageMagick) on its violet gradient, and a monochrome layer for themed icons.

## Motion

Motion should feel quick and never get in the way of work. The app runs in WebKitGTK, where layout on every frame, blur and filters are expensive.

- **How often decides how much.** Things done many times a day (switching channels, moving with the keyboard, the command palette, hover) don't animate, or take at most 100 ms. Occasional things (dialogs, menus, the drawer, toasts) take 150 to 200 ms. Only rare moments (onboarding) may be playful. Rows in long lists (the sidebar, Inbox, Later, messages) show their hover background at once; folding a section shows or hides its rows at once, with a short fade in.
- **Exits are faster than entrances**, and nothing blocks input while it animates. Modal surfaces (dialogs, Settings, the sidebar drawer) have no exit at all and leave the moment they close: an exit that never finished, as on a loaded WebKit, left an invisible modal blocking every click.
- **What a key changes changes at once.** A selection highlight moved by the arrows, Alt+↑/↓ or typing jumps; moved by a click, it slides briefly. `instantAfterAKey(transition)` picks, from the last input `useInputModality` saw.
- **Only transform and opacity animate**, never width, height, filters or `backdrop-filter`. The one exception is a row leaving a list (Inbox, Later, join requests), which collapses so the rows below close the gap.
- **Fades and pop-ins are tweens** with one strong ease-out. **Springs** are for things that move in space and may be interrupted (panels, selection highlights), and are short and bounce-free; only `springs.pop` bounces a little.
- **Reduced motion** is decided once, globally: `MotionConfig` in `main.tsx` follows the system unless Settings › Appearance › Reduce motion says On or Off. Motion then drops movement and keeps fades. Don't override it in components.

The tokens are in `ui/motion.ts`, and the same numbers are in the `@theme` in `styles.css` for CSS transitions:

| Token | Value | Use |
|---|---|---|
| `easeOut`, `--ease-out` | `cubic-bezier(0.23, 1, 0.32, 1)` | every tween and CSS transition |
| `durations.exit`, `duration-exit` | 80 ms | floating surfaces and content leaving |
| `durations.fast`, `duration-fast` | 100 ms | hover feedback (the default for a bare `transition-colors`), a scrim leaving |
| `durations.base`, `duration-base` | 150 ms | fades and pop-ins: menus, popovers, dialogs, content; Motion's default |
| `durations.panel`, `duration-panel` | 200 ms | panels sliding |
| `duration-highlight` | 500 ms | a message you jumped to: its highlight fades slowly |
| `tweens.exit`, `.fast`, `.base`, `.instant` | | Motion transitions for those durations |
| `springs.move` | 200 ms, no bounce | the drawer, the side panel, the docked sidebar |
| `springs.snappy` | 160 ms, no bounce | a selection highlight moved by a click, a chevron turning |
| `springs.pop` | 200 ms, a little bounce | a reaction added, a count changing |
| `rise`, `pop`, `fade` | | enter and exit variants for content, floating surfaces, scrims |

`tests/ui/design-rules.spec.ts` fails on a number of seconds written into a transition (outside `ui/motion.ts` and endless loops like a spinner), on a numbered Tailwind duration like `duration-300`, and on Motion animating a width or height. `tests/ui/motion.spec.ts` checks the timings in a real page.

## Layout

The app is for desktop windows, full screen (1280 to 2560 px wide) and split screen (640 to 1280). The smallest window is 640 × 560 (`tauri.conf.json`); a tiling window manager may go smaller, where nothing breaks but it needn't look great.

- **Widths are tokens** in `styles.css` (`@theme static`), never hand-picked in components: `w-sidebar` (264 px) and `w-sidebar-compact` (232 px), `w-side-panel` (380 px), `max-w-reading` (760 px, Inbox, Later and pages), `--width-channel-min` (560 px). Where things change is a token too: the window breakpoints `sidebar-docks` (900 px) and `sidebar-full` (1100 px), and the container widths `header-labels` (720 px), `header-pills` (480 px) and `composer-hints` (460 px).
- **Shared sizes of surfaces and cards** are tokens too (`@theme` in `styles.css`): `max-w-tooltip` (320 px; a tooltip wraps long text itself, breaking a long link anywhere), `max-w-card` (440 px, message and page cards), `w-popover` (320 px, profile card and time zone picker), `w-emoji-picker` × `h-emoji-picker`, `min-w-menu` and `h-settings`. A one-off size can stay where it's used.
- **Regions react to their own width** with container queries, not the window's: `@container/main` (the main column), `@container/header` (a view's header), `@container/composer` and `@container/settings`. So a docked thread panel narrowing the channel works the same as a narrow window. Write `@max-header-labels/header:hidden`, `@2xl/main:px-12` and so on.
- **JS only where behaviour changes**, reading the same tokens (`lib/layout.ts`): the sidebar docks or becomes a drawer, and a side panel docks or slides over. Nothing else measures widths in code.
- **On macOS the app draws the title bar** (`shell/TitleBar.tsx`): the window uses an overlay title bar with no title, and a `h-title-bar` (28 px) strip across the top, in the sidebar's colour with a line under it, holds the window buttons where macOS puts them. Dragging it moves the window and a double-click zooms it, also while a dialog is open: the strip stays above dialogs' scrims, and pressing it doesn't close them. Full screen hides the buttons, so the strip goes too. Windows and Linux keep the system's title bar.
- **The shell owns the regions** (`shell/ShellLayout.tsx`): the sidebar, the main column, and whether a side panel fits. Views don't reinvent them:
  - *Sidebar:* docked from 760 px, so half of a laptop screen keeps it (232 px wide, 264 px from 1100 px). Below 760 px it's a drawer that slides over the content from the left: a modal (Radix Dialog) with a scrim, so focus moves in and back like a dialog's; Esc, a click on the scrim or choosing a channel, page, Inbox or Later closes it. At any width the `PanelLeft` toggle and Ctrl/⌘+\ hide or show it; hidden is fully hidden (no icon rail), remembered per device (`isSidebarHidden` in `lib/preferences.ts`), and the toggle then starts the view's header. The toggle that was pressed hands focus to the one that appears.
  - *Side panels* (`shell/SidePanel.tsx`, the thread): docked beside the content while the channel keeps 560 px, otherwise sliding over it from the right with a shadow and no scrim, so the channel stays readable at the edge. Esc closes one that's over the content (and only it: the channel's own Esc waits), and so does a pointer-down anywhere outside it. There's no scrim, so that click still lands where it was aimed and keeps focus; menus, popovers, tooltips and dialogs opened from the panel count as inside it, and the click on a thread's own summary line doesn't reopen it. A docked panel ignores outside clicks. Closing otherwise hands focus back to what opened it; the reply draft stays either way.
- **Headers** (`shell/ViewHeader.tsx`) are one line, always, and share one bar style (`HEADER_BAR`) with side panels, which draw their own header: title, `actions` and a close button. The title is the only thing that shrinks and truncates. Below 720 px, `HeaderAction` buttons and pills keep only their icon, with the label as tooltip and accessible name ("Copy link", "1 agent can read this"); below 480 px a channel's pills move into one "Channel info" popover. The agent pill counts only agents who can read that channel: all of them in a public channel, only those in it (or invited) in a private channel or DM. A page's breadcrumb keeps only the parent page below 720 px. While the sidebar isn't docked, a header ends with your huddle's pill (where, mute, leave), since the huddle bar lives in the sidebar.
- **Content:** messages wrap long words and links; code blocks and tables scroll inside their own box. The message box's key hints hide below 460 px. Pages pad less in a narrow main column. Settings' section list narrows below 672 px. Dialogs are never wider than the window minus 16 px each side; menus and popovers stay inside it.
- **Motion:** the drawer, a side panel over the content and the docked sidebar slide by transform with `springs.move`, and slide away faster; the scrim fades. A docked side panel only fades in, since the channel reflows to make room anyway. The docked sidebar leaves the layout as it slides away, so the content takes its new width at once rather than on every frame. A key (Ctrl/⌘+\, Esc, Enter on a toggle) shows or hides them at once.
- `tests/ui/layout.spec.ts` checks each view at 640 × 560, 800 × 800, 1024 × 800, 1280 × 800 and 1600 × 900: no sideways scroll, one-line headers, a title at least 120 px wide, and every header action reachable. `sidebar-drawer.spec.ts` and `thread-panel.spec.ts` cover the sidebar and side panel behaviour.

## Components

| Component | For |
|---|---|
| `Button` | actions; variants `primary`, `secondary`, `ghost`, `danger`; sizes `sm`, `md`, `lg`; `isLoading` |
| `IconButton` | icon-only actions; `label` is required and becomes the tooltip and accessible name; `shortcut` adds its keys to the tooltip |
| `Input`, `TextArea`, `Field` | form controls; `Field` links its label, hint and `error` to the control through a render function (the error replaces the hint and turns the control's border red) |
| `Select` | a choice from a list (`options`, each with an optional icon), drawn by the app and styled like `Menu`, because the system's list can't be styled in the webview (Linux's WebKit draws its own); keyboard and typeahead from Radix; `isActive` tints it like a chosen option, for a filter that's narrowing a list; never a native `<select>` |
| `FormError` | why a form's last save failed, under the form; announced to screen readers |
| `Dialog` | modal surfaces (centered, or `placement="top"` like the search palette); never taller than the window, longer content scrolls inside; `hasCloseButton` for dialogs without their own Cancel or Done; on closing, focus goes back to what had it when the dialog opened (unless the dialog's action moved it on purpose, like into the message box), or to `returnFocusTo` when that is gone, like a card; pads its content and stacks it 16 px apart (`padding="none"` for edge-to-edge layouts like the palette and Settings); end with `DialogActions` for the buttons, the main one last |
| `ContextMenu` | actions on right-click at the pointer, styled like `Menu` (an image's Copy image); a message's own right-click menu leaves it alone |
| `Menu`, `Popover`, `Tooltip` | floating surfaces anchored to a trigger (a tooltip's `shouldShow` can keep it closed, like while the label it repeats is on screen); a menu sets destructive actions apart below a line, in red with their icon in the same red (other icons are muted), and runs the chosen action once it has closed and focus is back on its trigger, so a dialog the action opens keeps its own focus and returns it there; `Popover` can hand focus back to a field (`returnFocusTo`) |
| `Card`, `SectionLabel`, `EmptyState` | grouping and empty screens |
| `Avatar`, `Badge`, `Kbd`, `Spinner`, `Logo` | small content pieces; `Avatar`'s `isSpeaking` (passed only where speaking can show) draws a green ring that fades in and out, never pulses |
| `memberColor`, `memberTint` | a member's colour, as their avatar has it, for marks that stand for them (a caret, a name label) and, faint, for highlights behind text; screens take a member's colour from these, never build one |
| `AvatarStack` | who's somewhere, at a glance: a few overlapping avatars and "+N" (the huddle button); arrivals pop in, leavers fade, the rest close the gap at once |
| `ListRow` | a clickable row in a list (Inbox, Later, Drafts & sent, Files): `leading` avatar or icon (lined up with the meta line, or centered on the text with `leadingAlignment="center"` for a thumbnail), a small `meta` line, a one-line preview, an optional `footer` line under it (how people responded); `trailing` actions sit outside the button; `isHighlighted` keeps the hover background (while its menu is open) |
| `DayDivider` | a day's heading in a dated list ("Today", "Monday, April 27"); no side margin, so it spans what the list gives it and lines up with the rows (a channel wraps it in its 20 px gutter) |
| `CountBadge` | a count pill ("3", "@2", "4 new"), `accent` or `danger`, or `quiet` (grey) for things only waiting, like drafts; takes motion props so it can pop in when the count changes |
| `Notice` | a callout inside a screen: `info` (read-only and other things to know), `warning` or `danger` (something to fix), with an optional title |
| `InlineNotice` | a one-line problem and the one `action` that fixes it, for narrow places where a `Notice` is too big (the huddle bar) |
| `RelativeTime` | a past moment as short as stays clear ("Yesterday 4:41 PM"), the full date on hover |
| `SegmentedControl` | picking one of a few options: a radio group (arrow keys move the choice) named by `label`, sized to its options or `width="full"` |
| `ThemeSwatches` | picking a theme: a radio group of cards, each a tiny window in the theme's light and dark colours with its name and an optional small `detail` ("the workspace's default"), three to a row; `disabled` for someone who can only look |
| `Switch` | an on/off setting with its `label` beside it (the label toggles it too) |
| `CopyButton` | copies a value; its icon turns into a check for 1.5 s and a polite live region says "Copied" (the one micro-animation for copying, also inside `CopyField`) |
| `CopyField` | codes and commands with a copy button |
| `EmojiPicker` | a searchable emoji grid (names and keywords), recently used first, inside a `Popover`; it and its data load on first open, ship with the app and are never fetched from the network |
| `ConfirmDialog` | asks before something that can't be undone (deletes), showing what it applies to; stays open showing the error if it fails |
| `Toasts` | transient messages above the message box, from `lib/toast.ts`: `showToast` (a success, or `"info"`), `showUndoToast`, `showReminderToast` (with Open) and `reportError` (announced as an alert) |

Dialogs, menus, popovers and tooltips use [Radix](https://www.radix-ui.com/primitives) primitives for focus handling and keyboard support, styled by us.

## Editor

Pages are markdown in a CodeMirror editor (`features/pages/`), under a title field that grows to fit; a new page starts in its title, and Enter moves on to the body. The text people and agents share is always plain markdown; the editor only changes how it looks (live preview, like Obsidian):

- Lines nobody is editing read as formatted text: marks (`#`, `**`, `_`, backticks, link brackets and addresses, `>`) are hidden, list dashes become bullets, `- [ ]` becomes a checkbox, `---` a divider, and a quote starting `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` or `[!CAUTION]` (GitHub's callouts; `[!INFO]` is a note) a coloured callout with that label. Lines touched by your cursor or selection show their markdown, so you edit what is really there. While a mouse button is down nothing changes, so text doesn't jump under the pointer.
- Code blocks hide their ``` fences until you edit those lines, keep the language name as a small label, and colour the code by that language. Messages colour code the same way: one highlighter and the `tok-*` classes in `styles.css` (`lib/codeHighlight.ts`, CodeMirror's parsers loaded per language on first use).
- A table shows as a real table until the cursor enters it; clicking a cell puts the cursor in that cell's text, and while you edit, the table's markdown shows in monospace so the columns line up. Messages render tables and callouts too, with the same callout colours (`lib/callouts.ts`, `callout-<kind>` in `styles.css`).
- Page links (`shy://page/<id>`), message links (`shy://message/<id>`), links to the page's files (`[name](shy://file/<id>)`) and mentions are chips, also on the line being edited; the cursor steps over a chip as one unit. Page chips show the page's current title and open it on click. Message chips show the link's own label, or "a message" for a bare link as in chat, and open the message in its channel or thread; one that's gone says "That message was deleted." File chips show the file's current name and open the file viewer (with Save); a link to a file that isn't one of the page's reads "File unavailable" and opens nothing. Mention chips open the person's profile card (click, or Ctrl/Cmd+Enter beside one), placed at the chip, without moving the cursor; Esc goes back to the editor. A mention of someone who isn't a member opens nothing.
- Others on the same page show as a caret and a low-opacity selection tint in their avatar's hue. Their name shows above the caret for 2 seconds after it moves and on hover, so it never sits over the text for long, and a caret that hasn't moved for a minute fades. The page header lists who else is there as small avatars; clicking one scrolls to their cursor. Settings has "Others' cursors in pages" (Appearance) and "Your cursor in pages" (Privacy), both remembered on this device.
- A page's images (`![caption](shy://file/<id>#width=N)`, only files shared into that page) are blocks the cursor steps over like a chip, centered at N% of the text column (or their own size, at most the column). Before the image loads, its box is 4:3 on `bg-surface-2` with a quiet image icon, no spinner; then it fades in, rounded-xl. Anything that can't show (not this page's file, not an image, too large) is a one-line "Image unavailable" card, with Save when the file is the page's. A selected image shows an accent ring, never the text selection's tint or a caret; a selection running through one tints only the text around it. Hover or select one for its two edge handles: dragging resizes it around its center line in whole percents with a small "60%" label, and with it selected (Shift+arrow over it), Alt+←/→ resize by 10 and Alt+0 goes back to its own size. The caption (its alt text) sits centered under it in `text-sm text-muted`; click it, or press Enter with the image selected, to edit it in place (Enter or leaving saves, Esc cancels); an image without one takes only its own height, and shows "Add a caption" under it only while it's selected. Clicking the image opens the file viewer.
- Web links show their address on hover and open with Ctrl/Cmd+click.
- Menus under the cursor: `/` (at the start of a line or after a space) for blocks, `@` for people, `[[` for pages. They open only when you type the trigger, never for another member's edit; arrows, Enter or Tab and Esc drive them while the editor keeps focus and points at the chosen option with `aria-activedescendant`. Each choice inserts the markdown you could type yourself.
- Keys write markdown: Ctrl/Cmd+B, I and E wrap the selection in bold, italic or code (again to undo it, or to step out of an empty pair); Ctrl/Cmd+K links the selection, and without one stays the app's search; Ctrl/Cmd+Enter checks off the item, opens the link, or shows the mentioned person's card at the cursor. Undo and redo only touch your own edits.

Rules for changing it:

- Decorations never change the document. A widget that acts (a checkbox) makes an ordinary edit, computed from the document as it is at that moment, never from a remembered position, so it stays right while others edit.
- `editor/markdownPreview.ts` decides what to hide or draw and is pure (tested in `tests/ui/markdown-preview.spec.ts`); `editor/livePreview.ts` turns that into decorations. Only the visible part of the page is decorated, so long pages stay fast. Tables are block widgets, which CodeMirror takes only from a state field, so `editor/tables.ts` draws them separately.
- Plugins may not hide a line break; keep each hidden range on one line.
- Styles live in `editor/theme.ts` and use the tokens; color only list markers, never whole list lines.

## Rules

- Formatted messages (`.prose-chat` in `styles.css`, drawn by `lib/markdown.tsx`) read like chat, not a document: headings at 1.375, 1.2 and 1.075 times the text (a page's are bigger) with more room above; one 0.5rem gap between any two blocks at every level, and list items, nested lists included, 0.125rem apart; a divider is a 1px `--border` line across the message with 0.75rem above and below; code never uses ligatures, so `=>` shows as typed. A one-line message stays one line tall. `tests/ui/chat-typography.spec.ts` measures these.
- Settings shows people only what they can act on (`sectionsShownTo` in `lib/settings.ts`): a member sees their own six sections and Members, where the admin and agents carry their tags; Workspace, Agents, Storage and Recovery are the admin's, and so is the storage warning in the me menu. The core refuses those actions from anyone else anyway: hiding is for clarity, not security.
- Files: the message box takes files from its paperclip button, by dropping them on the window (they go to the message box or page of the panel they land on, the channel, its thread, a DM or a page, and to the one used last when dropped elsewhere, like on the sidebar; only that box shows "Drop to attach" while they're dragged over it), or by pasting (when the web view hands over an empty paste, the image is read from the system clipboard instead, `lib/clipboardImage.ts`). A page takes pasted and dropped files at its cursor: an "Uploading <name>…" line with a thin bar holds the spot, and the link is written only once the upload is done (an image as `![](shy://file/<id>)`, anything else as `[name](shy://file/<id>)`); a failed upload leaves nothing behind but its error. A pasted clipboard image is named after the page ("Plan image 2.png"). They wait as removable chips above the text, with a reason under them when they can't be sent (more than 10, or over 150 MB); a thin bar shows the upload, and if sending fails the files and text stay. In a message, images show inline (up to 25 MB, and only when their bytes really are an image) and other files are a card with their icon, name and size; either one shows Save and a "⋯" menu on hover or keyboard focus, and right-click on a card opens that menu (on an image: Copy image and Save image). The menu holds Save, and Rename and Delete for those who may, below a line, so Delete is never one slip from Save. A click opens any file in the viewer: a bar with its name, who shared it, where, when and its size, then Show in chat (outside chat), Save, the menu and Close; Esc, Close or a click on an image closes it, and opening focuses the viewer itself so the keys scroll it. Images show large; PDFs up to 25 MB are drawn page by page (the first 30 pages, then a note to save it for the rest); text files up to 1 MB (`.txt`, `.md`, `.csv`, `.json`, code, logs) show as text, markdown formatted by `ChatMarkdown`, and bytes that aren't UTF-8 text say so; anything else says there's no preview and offers Save. The Files view (sidebar) lists every file you can read newest first, grouped by day with `DayDivider`, each row a `ListRow` saying who shared it, where, its size and when, with the same hover actions plus Show in chat and the same right-click menu. Above it, name search across the full width, then one row of filters (`drive/FileFilters.tsx`): kind (by the same kinds that pick a file's icon), who shared it and where (a `Select` each, with avatars and channel marks, listing only people and places that have files); a filter in use is tinted, a narrow window gives the kinds a row of their own, and when nothing matches, Clear filters resets them. The pieces shared by the message box, messages and the Files view live in `features/files/`: `FileThumbnail` (the image itself once loaded, its kind's icon otherwise), `FileActions` (the buttons and menu, with the rename and delete dialogs), `FilePreview` in `FileViewer.tsx` (picks the image, PDF, text or no-preview viewer); images load through one hook, `useImage` in `lib/files.ts`. Renaming opens a small dialog with the name before the extension selected, so typing keeps `.png`. Avatars show a member's picture once it has loaded (`members/MemberAvatar.tsx`); `ui/Avatar` only takes the picture's URL.
- Huddles (`features/huddles/`): drop-in voice rooms per channel or DM, up to 8 people. A channel's header has one button: Huddle (start one), the faces of who's in and Join, Full, or Leave; one click, no lobby, and Ctrl/⌘+Shift+H does the same where you are. Joining another huddle leaves yours, with Undo. A sidebar row shows a quiet headphones mark and how many are in (accent while it's yours), never a badge; channels never ring, and someone starting a huddle in a DM raises one desktop notification that opens the DM. While the app rings for it (never while you're in a huddle), a card sits where the huddle bar goes: who started it, Join and Decline; it leaves the moment the ring stops (answered on any device, declined, the caller gone, or no answer), and with the sidebar hidden it's a pill in the header. Nothing in it moves after it arrives: the ring is the alarm. While you're in one, a bar sits at the bottom of the sidebar on every view: the place (a link to it), a status after it only when it matters (Reconnecting…, Muted, Just you so far, Connecting…), everyone's faces with a green ring on whoever talks, faded while their audio connects, then Mute with ▾ for the microphone and speakers, and Leave in red text. Mute says its state in words ("Mute", "Unmute", "Unmuting…" while the closed microphone reopens), is tinted while muted, and Ctrl/⌘+Shift+Space toggles it. Microphone and headset trouble shows as one `InlineNotice` with its fix (no permission, a silent microphone, a microphone or speakers that stopped working while the app retries, a headset dropped to call quality); a device trouble shows only after 2 s, since a chosen device unplugged hands over to the default within a second. A reconnect shows only after 3 s, so blips stay invisible; "relayed" is only a line in the details. The details popover lists everyone with how they're connected and who needs an update, then the device pickers (System default first, which follows the system's choice; an unplugged choice stays chosen and says the default plays meanwhile), which Settings › Huddles also has, with "Join huddles muted" and "Play huddle sounds" (a soft tone on joins and leaves, heard only in the huddle); in a build without voice, that section only says why. A polite live region (`HuddleProvider`) says joins, leaves, mute and trouble, never who's speaking. Faces in the header show only who's in, never how their audio is doing.
- `@` in the message box suggests people, and once you type a letter, up to three pages whose title has a word starting with it, under a "Pages" label. A picked page shows as `@Title` while you write and is sent as its link, which reads as a page chip. Someone's whole name typed after `@` (any case) mentions them without picking, on a space or when sent; part of a name, or a name two people share, stays plain text. Dragging a page from the sidebar onto the message box does the same at the cursor (`lib/pageDrag.ts`); dropped elsewhere, like into a page, it's the page's link.
- Members who share a name are told apart by the start of their safety code: "Grace · 1234 5678" in member rows, pickers and the confirms to remove someone or hand over a channel, and "@Grace·12345678" when mentioned (the suggestion shows the code beside the name).
- The message box offers emoji three ways, all from the app's own emoji set and sharing one "Recently used" list: the smiley button (inserts at the cursor), `:` and two or more letters (suggestions by shortcode or keyword, in the same keyboard-driven list as `@` mentions, `chat/useSuggestions.tsx`; not inside code, links or times like `10:30`), and "More emoji…" beside the quick reactions. The emoji data loads only on first use.
- A message shows at most 20 reaction pills; any more sit behind a "+N" pill ("Show N more reactions") that reveals them. Sent shows the same 20 and a plain "+N".
- Creating a workspace asks for the storage bucket. The Endpoint field takes an endpoint or a bucket's own address and recognises common providers (`lib/storageEndpoint.ts`: Scaleway, AWS, Cloudflare R2, Backblaze B2, Hetzner, DigitalOcean Spaces, Wasabi): a bucket's address becomes the provider's endpoint plus the bucket, the region is filled in, and the hint under the field names the provider and place ("Scaleway, Paris"). It never overwrites a bucket or region the person typed, leaves unknown addresses (MinIO, self-hosted) as typed, and the connection test still decides. Settings › Storage names the provider beside the endpoint too.
- Several workspaces (`shell/WorkspaceRail.tsx`, `shell/Workspaces.tsx`): with two or more on the device, a 52 px rail of workspace icons (the picture the admin set in Settings › Workspace, or the letter tile, like an avatar) sits before the sidebar's content, docked or in the drawer, and hides with the sidebar. The shown one has a short accent bar at its edge; another shows a short dot at its edge for unread and a red count for mentions and DMs (the sidebar's own counts), and is dimmed with nothing on it while muted. Hovering names it with its key: Ctrl/⌘+1…9 picks a workspace by its place. Right-click (or the menu key) offers Mute notifications, Mark all as read, Move up or down, and Leave workspace…; "+" at the foot, or Add a workspace… in the workspace menu, opens create, join or restore with a way back. Switching is instant: the shell remounts on the other workspace, with no transition. Leaving asks first and says the workspace's messages, pages and files are removed from this device; the next one shows, or onboarding if none is left. Notifications from any workspace name it once there are two ("Team · Grace in #design"), and clicking one switches there and opens the message. The me menu's "Pause notifications everywhere" (an hour, or until 9:00 tomorrow) holds every workspace's notifications, shown by a muted bell-off by your name; with one workspace, the status's alert setting does that instead. One call runs at a time across the device: while another workspace is shown, its bar (or header pill) names where it is ("Acme · #general", a link back there) with Mute and Leave, since its people and devices belong to that workspace. A ring from another workspace shows its card with "in Team", and Join goes there to answer. Reminders, away and back, and the window's badge count (the sum of every workspace's) cover every workspace too, and switching first saves a draft, page typing and how far you've read in the workspace you're leaving.
- Back and forward (`lib/history.ts`, wired up in `lib/useNavigation.ts`): changing channel, opening or closing a thread, opening a page, Inbox, Later, Drafts & sent or a search result each add a place; dialogs (Settings), the search palette, cards, scrolling and reopening the place you're in don't. Up to 50 places, in memory. Keys: Alt+← / Alt+→ (⌘[ / ⌘] on a Mac, where Option+arrows move by word) and the mouse's back and forward buttons, also while typing; keys the page editor already uses stay the editor's. Places that were deleted or can't be opened any more (including a private channel you were removed from) are skipped and forgotten, with a notice only when every place that way is gone; a thread whose first message was deleted opens its channel.
- Coming back to a channel opens it where you left it: through history always, and from the sidebar when it has nothing unread (otherwise at the new-messages line). Positions are a scroll anchor (`lib/scrollAnchor.ts`: the top visible message and its offset), never raw pixels, so they survive history loading and text rewrapping; at the newest message there's no anchor and the channel opens as usual. The app reopens at the last view (with its thread and anchor), the only part of the history kept on the device (`lib/lastView.ts`).
- Reading (`chat/useReadPosition.ts`): a message is read only once its bottom edge has been on screen while the window has focus, isn't hidden, and its channel (or thread) is the view you're in. The read position is the newest such message, only moves forward, and is saved within about 300 ms of moving, when you leave, and when the window loses focus or hides; a channel opened again right away uses the position just sent, even if the core's answer is still on its way. Threads keep their own position. Sidebar counts, @-badges and the Inbox all come from these positions; nothing keeps a separate count.
- The new-messages line goes above the first unread message as you open a channel and stays put for that visit; messages that arrive while the window can't be looked at get a line above the first of them. Esc marks the channel read, removes the line and both pills, and goes to the newest message.
- Pills over the list (`chat/UnreadPills.tsx`, primary `Button`s announced politely): "Jump to unread ↑" shows on opening when the first unread message is above the view, and goes for that visit once the line is on screen, it's clicked, or Esc. "N new messages ↓" shows only while you're scrolled up and others' messages arrive (N counts them), and goes at the bottom, on click, on sending, or on leaving.
- Following (`chat/useHeldScroll.ts`): content arriving keeps you at the newest message while you're there; scrolling up by any means (wheel, keys, dragging) stops that at once, and scrolling back down within 24 px resumes it. Otherwise the top visible message stays exactly where it is as anything loads or changes size, moved only by the difference so a fling carries on (the browser's own `overflow-anchor` is off, so WebKit and Chromium behave the same).
- Keyboard shortcuts are defined once in `lib/shortcuts.ts` (the shell handles them, the cheat sheet and menus show them). Use a modifier key: the message box usually has focus, so plain letters belong to typing.
- The logo lives in `docs/brand/`: `mark.svg` (the app icon and `ui/Logo`), `logo-light.svg` and `logo-dark.svg` (wordmarks), and `logo.svg` (a mid-tone wordmark that reads on any background, for places that can't tell light from dark, like the README). After changing the mark, copy it to `apps/desktop/app-icon.svg` and run `pnpm tauri icon app-icon.svg`.
- Need something new? First check whether an existing component (or a variant of it) fits. Add a component to `ui/` only when a third screen needs the same thing.
- New components go in `ui/`, get an entry in `ui/index.ts`, and appear in the gallery.
- `tests/ui/design-rules.spec.ts` keeps this from drifting: it fails on a hand-picked font size anywhere, and in `features/` on raw colours (`text-white`, palette colours like `bg-red-500`, hex, `rgb()`) and on native `<button>`s with a solid accent, danger, success or warning fill (use `Button`).
- Every interactive element works with the keyboard and has an accessible name.
- Focus rings are for moving with the keyboard. `lib/useInputModality.ts` marks how the app was last used: Tab, the arrows, Home, End, Page Up/Down, Enter and Space count as keyboard, alone or with Shift; other typing, Esc and anything with Ctrl, Alt or Super (window manager and app shortcuts) don't, nor do keys in the first 150 ms after the window gains focus (Wayland passes on the keys still held from switching windows) or their repeats. Arrow-key lists (suggestions, the palette, the calendar) also ignore arrows with Ctrl, Alt or Super. So a clicked row stays without a ring when you then press a key, and focus that Radix moves after a click (back to a menu's trigger, into a dialog) gets none either. Controls that show on hover also show for keyboard focus with `keyboard-focus-within:`, not `focus-within:`, which stays on after a click.
- Two kinds of ring, both in the accent: buttons and other controls get a 2 px ring 1 px outside (text fields show focus with their accent border instead); rows in a list (sidebar items and the page tree, `ListRow`, the sidebar's two menu buttons, Settings sections, status presets) add `focus-ring-inset`, a 1.5 px ring drawn inside the row, so a scrolling sidebar or list never cuts it off and it shows on a selected row too. The accent keeps 3:1 against `bg`, `surface` and `surface-2` for every preset (`tests/ui/contrast.spec.ts`). Big containers (scrolling panels, tab panels, the message list) never show a ring: a tab panel that holds controls isn't a tab stop (`tabIndex={-1}`), and they all use `outline-none`.
- Fields with a format (an email, a phone, a website) say what's wrong once you leave them or press Save, never while you type; Save then moves focus to the first one to fix. Give them a one-line hint, so the message takes its place and nothing moves under the pointer between pressing and releasing Save.
- Saving: choices and toggles apply at once. Text forms have one Save button named for what it does ("Save profile"). Never mix the two in one form. A failed save keeps what the user typed and shows why with `FormError` (`lib/useFormAction.ts` does both).
- Settings is one fixed-size window: sections under "You" and under the workspace's name. Open it at a section from anywhere with `useWorkspace().openSettings({ section })`; every section is also in the command palette ("Settings: Notifications").
- The sidebar has two menus: the workspace's name at the top (Invite people, join requests, Workspace settings) and you at the bottom (Set status, Appear offline, Settings). Personal things that change often, like status, live in your menu, not in Settings.
- Under a thread's first message, one line sums up its replies (`chat/ThreadSummary.tsx`): up to three small avatars of the latest repliers (newest first), "N replies" in the accent (semibold with a "N new" badge while some are unread), the last reply's author and a plain one-line preview, and its time. The preview is cut first when space runs out; the count never wraps. The whole line is one button that opens the thread; hover gives it a `surface-2` background and a chevron.
- Status beside names: only the emoji, never the text, in message headers (once per group, so threads too), the member list and the `@` suggestions; hover or keyboard focus tells the whole status ("🌴 On holiday · until Fri 18:00", `members/StatusEmoji.tsx`). A status without an emoji shows nothing there. Ended statuses disappear on their own, live (`lib/members.ts`). Presence dots show only in the member list and the `@` suggestions, never in messages. Agents show their tag instead of a presence dot, and no status.
- Profile cards (`members/ProfileCard.tsx`): clicking, Enter or Space on a name or avatar in a message header, or on an @mention, opens a card as a popover with focus inside (on the card after a click, so no ring shows; on its first action after Enter or Space); Esc or clicking outside closes it and focus returns to the name. Pausing 600 ms on a header's name or avatar also opens it, without taking focus, and it closes 300 ms after the pointer leaves both the name and the card (WCAG 1.4.13); @mentions in text never open on hover. It's built on Radix Popover, not HoverCard, which the keyboard can't reach. Card and full profile share their parts (`members/ProfileParts.tsx`, `ProfileActions.tsx`):
  - *Header:* a 64 px avatar with the presence dot and, centred beside it and never taller than it, three lines: the name in semibold with pronouns muted, the title, then the Admin or Agent tag and presence (people only); under it the status with when it ends.
  - *Detail rows,* only for what's filled, one line each with a small `text-decorative` icon: their local time ("11:42 PM local time · 8 h ahead", or "Same time as you"; "Outside working hours" on a small second line in `warning-text`, so it's never cut), updated as each minute starts; location; email, phone and website, each a link that opens with the system's handler, shows its full address on hover and has a `CopyButton`; a website reads as the host and path it really opens ("ada.example.com/about"), parsed from the address. No stagger: rows appear with the card.
  - *Bio:* three lines at most (`line-clamp-3`), its web addresses as links (one naming a user before its host stays plain text), and "View full profile" when it's cut.
  - *Actions,* below a line, all `sm` buttons: Message (primary; agents too) and Mention for others; Set status (primary) or Clear status, and Edit profile, on your own (Edit profile opens Settings › Profile at the first key field still empty). Everything rarer waits in the "More actions" menu: View full profile, Copy name, View their messages (search `from:"name"`), Agent settings (the admin, on an agent), View in members.
  - *Full profile:* a `Dialog` with the same header, every row including working hours, the whole bio and the same actions. It isn't a step in history; closing it puts focus back on the name that opened the card (`returnFocusTo`).
- Profile details elsewhere stay quiet: pronouns show muted after the name in the `@` suggestions (titles don't fit their one-line rows), and the member list puts the title before the status or presence under each name. Message headers show neither. In a 1:1 DM, while it's late for the other person (outside the working hours they shared, or without hours from 20:00 to 08:00 their time), one muted line above the message box says so: "It's 11:10 PM for Theo · outside their working hours" (`chat/LocalTimeHint.tsx`). It never blocks sending, has no dismiss button, and goes when their day starts. When they're two or more hours off your clock, the DM's header also shows a small clock and "10:00 AM their time" after the name (`text-2xs`, faint), all day; closer than that it says nothing, since the hour is the same as yours or near it. A 1:1 DM's row in the sidebar shows their status emoji after the name, with the whole status in its accessible name.
- A channel named in visible text uses `private/ChannelName.tsx`: # and the name, a lock for a private channel, or a DM's person (avatar and name), never a hand-written `#name`. Accessible labels and dialog titles use the `channelReference` string from `lib/channels.ts`.
- Updates: once a new version is downloaded and checked, an "Update ready" card docks at the foot of the sidebar (`shell/UpdatePrompt.tsx`): "shyspace 0.2.0 is downloaded." and a Restart button; with the sidebar hidden, a small pill in the header does the same. No dismiss, no timeout: it stays until you restart. Restart turns into a disabled "Restarting…" for as long as installing takes (Linux asks for an admin password then); a failure shows its reason under the button and Restart works again; during a huddle Restart waits, saying "Restart after your huddle.", and comes back when you leave.
- A warning uses a small triangle (`TriangleAlert`, `text-danger`) with an accessible name and a tooltip saying what's wrong. It marks the way to a problem that lasts until someone fixes it, like storage that can lose data (the "me" button, Storage in Settings, and a "me" menu item). Its notice in Settings has no dismiss button. Dots mean presence or unread, never a warning. The same sign marks a storage key a removed member still has: Settings › Storage then opens with a "Change the storage key" card (`settings/KeyRotation.tsx`) of numbered steps, each ticked when done: create a key at the provider (its menu path and guide, told from the endpoint), save it in the form below (and the new recovery kit), let everyone move (a list of who has, and how many a delete now would cut off), then delete the old key and check. "Don't change the key" asks first, saying the removed member's key may still work.
- Sidebar counts mean "this needs you" (unread messages, mentions, a reminder that's due): a coloured badge and a bold label. Things that are only waiting get no count, except drafts: Drafts & sent shows how many in a `quiet` badge, with the label left as it is.
- Drafts & sent (`drafts/`) has two tabs. Drafts live there only, not in the Inbox: one row per conversation or thread with unsent text, last edited first, marked "Old" after 7 days; Discard has Undo in a toast, never a confirm dialog. An unsaved edit of your message is a draft of its own (`chat/useEditDraft.ts`), kept once its text changes and apart from the conversation's draft: "Editing a message in #general" ("Editing a thread message in" for a thread), and opening it, or the conversation, carries on editing with the cursor at the end; saving or Esc removes it. If the message was deleted meanwhile, the row says "Edit of a deleted message in", and opening the conversation puts the text in the message box after any draft there, with a notice. Sent lists your messages newest first, grouped by day like a channel, 50 at a time, with a filter that matches words by their start. Each row shows how people responded: the thread's repliers and count, reaction counts, and "No replies yet" when nobody else replied or reacted to a message that starts a conversation and asks something (has a "?") or mentions someone (`drafts/responses.ts`). Edit and Delete happen in the conversation, which a row opens. Ctrl/⌘+Shift+D opens it with focus on the chosen tab; ↑ and ↓ step between the tab, Sent's filter and the rows (the rows' `data-list-row` buttons), Enter opens a row, and Delete or Backspace discards the draft you're on, moving focus to the next row.
